1.1 Evaluated intensity levels (normalized alpha grid)

  For Paper 3 Experiment 2, the unified runner is invoked with a fixed list (same for all models in this run):

    ALPHA_GRID = [0.0, 0.25, 0.5, 0.75, 1.0]

  Source: architecture_refinement/paper3/run_paper3_experiment2.py (constant ALPHA_GRID).

  - Total points: 5
  - Spacing: linearly spaced in alpha (step 0.25 from 0 to 1).
  - This is NOT 11 equally spaced levels in raw sigma; it is five normalized alpha values.

1.2 Mapping from intensity to AR(1) noise strength

  In evaluation/unified_experiment_runner.py, _evaluate_perturb, for correlated noise types including
  ar1_drift, when test_perturb_gaussian_alpha_grid is set:

    intensity = alpha * alpha_max

  where alpha_max is produced by _get_alpha_max_for_correlated_noise(noise_type, X_valid, split_id=...).
  That routine calibrates noise power so that at intensity=alpha_max, the signal-to-noise ratio matches
  test_perturb_target_snr_db (default in Exp2: -5.0 dB for this manifest; see experiment2_manifest.json).

  Therefore:
  - sigma(p) is NOT "p * RMS(signal)" as a single global formula in code.
  - Instead: alpha is the normalized knob in [0,1]; alpha_max is data-dependent per (split, fold, session)
    calibration using a fixed calibration seed _CALIBRATION_SEED = 202602 (see unified_experiment_runner.py).

1.3 AR(1) process parameters (fixed vs variable)

  - phi (AR coefficient): controlled by CLI --test_perturb_ar1_rho. Experiment 2 passes rho = 0.97 in
    perturbation_params for ar1_drift (run_paper3_experiment2.py: manifest uses pert_params
    {"ar1_drift": {"rho": 0.97}}).
  - This is fixed across models and seeds for a given launch (same CLI for all jobs in that pilot).
  - It is NOT 0.9 unless you explicitly changed the flag; the default pipeline uses 0.97.

1.4 Randomness and fair comparison

  Correlated noise augmentors use self.seed when no explicit seed is passed in the per-intensity loop
  (_make_correlated_noise_augmentor(..., seed=self.seed) for evaluation perturbations).

  Important nuance:
  - The same training seed and the same perturbation protocol apply to every model in the study.
  - Identical additive noise tensors across two different models are NOT guaranteed, because noise is
    applied to that run's validation tensor X_valid, which differs across sessions/folds and across runs
    if the underlying data slice differs.
  - For a single model and a single (model, seed), the sweep is deterministic given the code path.

SUPPLEMENTAL Q&A (from codebase)
--------------------------------------------------------------------------------

Q: How do we determine alpha_max for AR(1) noise?

A: For noise types in the correlated path (including ar1_drift), alpha_max is computed in
   evaluation/unified_experiment_runner.py by UnifiedExperimentRunner._get_alpha_max_for_correlated_noise.

   Procedure (same for AR(1) as for other correlated types; AR(1)-specific behavior enters only through
   the augmentor’s transform at unit intensity):

   1) Take the current validation tensor X_sample (epochs × channels × time) for the fold/session being
      evaluated. A cache key includes (dataset, noise_type, split_id, perturbation params including
      test_perturb_ar1_rho, target_snr_db).

   2) Build an EEGNoiseAugmentor with noise_type=ar1_drift, intensity=1.0, seed=_CALIBRATION_SEED (202602),
      and ar1_rho from --test_perturb_ar1_rho (default 0.97). Apply transform to get unit-strength noise:
      eps = augmentor.transform(X_sample) - X_sample.

   3) Compute mean signal energy per epoch (summed over channels and time, averaged over epochs):
        mean_X_sq = sum(X_sample**2) / n_epochs
      and mean squared noise at unit intensity:
        mean_eps_sq = sum(eps**2) / n_epochs
      If mean_eps_sq is invalid, fall back to alpha_max_0dB = 1.0.

   4) alpha_max_0dB = sqrt(mean_X_sq / mean_eps_sq). This is the scale factor such that using intensity
      equal to this value would correspond to the “0 dB” reference in the SNR definition used below (ratio
      of total signal power to total noise power in this aggregate sense).

   5) Let target_db = test_perturb_target_snr_db (Paper 3 manifests use -5.0). Then:
        alpha_max = alpha_max_0dB * 10^(-target_db / 20).
      So for target_db = -5 dB, alpha_max is larger than the 0 dB reference by a factor 10^(5/20).

   6) Invalid values clamp to alpha_max = 1.0. The result is cached so the same split/params/target_db
      do not recompute.

   Evaluation intensities on the normalized grid are then intensity = alpha * alpha_max for each alpha in
   test_perturb_gaussian_alpha_grid (e.g. 0, 0.25, …, 1). Rows in CSV may record alpha = intensity/alpha_max
   and alpha_max for traceability.

Q: How is alpha (normalized grid) mapped to actual noise magnitude?

A: Two steps: (1) normalized alpha on [0,1] becomes a scalar intensity; (2) intensity scales the AR(1)
   noise tensor added to the EEG.

   (1) From evaluation/unified_experiment_runner.py (_evaluate_perturb, correlated path):
        intensity = alpha * alpha_max
      where alpha is one entry in test_perturb_gaussian_alpha_grid and alpha_max is from
      _get_alpha_max_for_correlated_noise (see previous Q).

   (2) From augmentation/noise.py, EEGNoiseAugmentor._apply_ar1_drift:
      - For each epoch, an AR(1) process eps is generated per channel with rho = ar1_rho (default 0.97),
        innovations scaled so the stationary variance of eps is 1 per channel (sigma_eta = sqrt(1 - rho^2)).
      - The corrupted signal is:
          X_aug = X + intensity * eps
      So “actual noise magnitude” is linear in intensity: the additive noise field is intensity times a
      fixed-scale unit-variance AR(1) process (same random stream/seed behavior as elsewhere in that method).

   At alpha = 0, intensity = 0 and no noise is added. At alpha = 1, intensity = alpha_max (the SNR-calibrated
   ceiling for that validation split). Intermediate alphas linearly interpolate noise power between 0 and
   that ceiling in the sense of scaling eps, not by redefining eps.
